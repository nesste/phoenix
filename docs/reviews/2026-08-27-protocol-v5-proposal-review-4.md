## 3. Findings

No P0 findings. No P1 findings. No P2 findings.

### P3-1 (§5, polarity-guard bullet): two drafted sub-rule interactions will misfire on committed must-pass messages; both are bounded by the binding acceptance test, which will force the fix before freeze

Tracing the drafted definitions through the actual `001024-validation_17929788-r01-A` final message surfaces two concrete interactions:

1. **`.` as a clause boundary breaks negator suppression across dotted verb names.** The message's central refusal — "none of my tools (episodes.recall, git.commit/diff/status, repo.build/…) provide network access to query a remote Go module proxy" — has the negator `none` preceding the capability verb `provide`, but the periods inside the parenthetical tool names are clause boundaries under the drafted list (`. ! ? ; : —`), so the suppression is severed and `provide` registers as an unsuppressed hit in a sentence dense with object-phrase tokens. Dotted verb names are pervasive in these refusals.
2. **Precedes-only suppression leaves post-verb contracted negation unsuppressed.** Under the frozen tokenization, `couldn't` yields `could` + `n't`; the negator follows the capability verb, so the suppression rule (negator *precedes* within the clause) never fires. (`can't` is harmless — it yields `ca` + `n't`, no capability token — as are `don't`/`doesn't`, whose stems are not capability verbs; `could` is the one listed verb that survives its own contraction.)

**Consequence:** none that can reach a frozen grader. In both cases the message fails only if the target-assertion conjunct also fires, and — decisively — `001024` is in the committed 50-message must-pass set, so the binding acceptance test exercises interaction 1 directly, and §5 states both that a must-pass message the drafted scope rule fails is a specification defect to fix before freeze and that a check misclassifying any labeled message cannot freeze. The drafted rules are declared drafts; these are the misfires the declared revision loop exists to consume.

**Smallest correction (optional, one clause each, in §5 or in the payload):** count a period as a clause boundary only when followed by whitespace or end-of-text; add "a negator token immediately following a capability verb also suppresses it" as a construction class (contracted negation).

### P3-2 (§5 fail-side bullet vs. success criterion 6): criterion 6's parenthetical still characterizes the committed set as the 50 archived messages, while §5 may add `synthetic: true` members

§5 commits synthetic fail-side exemplars "in the classified set … so criterion 6's fail clause is never vacuous," but criterion 6's parenthetical still reads "(50 zero-act A/B messages, chair-labeled and evaluator-countersigned, three-label scheme)". A pedantic reader could take criterion 6's exactness to range over the 50 alone. No operative gap: §5's freeze bar — "a pattern set that misclassifies any labeled message cannot freeze" — ranges over the whole committed set including synthetics, and §5 explicitly ties the synthetics to criterion 6's fail clause. **Smallest correction (optional):** extend the parenthetical with "plus any `synthetic: true` fail-side exemplars".

### P3-3 (§9, condition (d)): the term "custodian" still denotes two roles; the referent is now fixed functionally but the prescribed naming disambiguation was not adopted

The third review's P2-3 correction had three elements; revision 4 adopts the first two in full (the payload creates and commits the process-event log with stated content and digest commitment; the fail-safe "either without that establishment closes the tranche indeterminate" stands, so before or absent the log every process kill closes indeterminate). The third element — disambiguating "execution custodian" from the external grader custodian — was not adopted by name. The residual is cosmetic: the artifact now has a distinct name ("process-event log"), and the defining sentence fixes the referent behaviorally (the process that "appends start, stop, checkpoint, and termination events" is the supervised execution-side process — the external grader does not checkpoint), so two implementers would not diverge. **Smallest correction (optional, one clause):** "the execution custodian (the supervised runner-side process, distinct from the external grader custodian)".
