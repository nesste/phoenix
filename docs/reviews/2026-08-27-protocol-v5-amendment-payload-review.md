## 3. Findings

No P0 findings. No P1 findings. No P2 findings.

### P3-1 (pre-existing, not introduced by this payload): status-precedence divergence between the in-repo grader and the external-grade consistency validator when a grade carries both a gating `fail` and a gating `manual_required`

`experiments/frontier-v1/corpusctl/internal/corpus/grade.go` `overallStatus` returns `fail` on the first gating fail regardless of any gating `manual_required`; `experiments/frontier-v1/runner/validation_grader.go` `validateExternalGrade` lets a gating `manual_required` set `wantStatus` to `indeterminate` even after a gating fail has been seen, so a grade containing both would be computed `fail` by the grader and demanded `indeterminate` by the validator. **Consequence:** none reachable in v5 — the identical precedence existed at the base commit (this is not a new defect; the payload's only change to both functions was the consistently-applied gating filter), the v5 grader no longer produces `manual_required` at all (`final_message_states`, its only source, now fails closed), and the external grader is digest-pinned to the same implementation; both statuses are ITT failures in any case. **Smallest correction (optional, at refreeze or a later payload):** make `validateExternalGrade` mirror `overallStatus` precedence (gating fail dominates gating manual).

### P3-2 (frozen doc, becomes stale at refreeze): `experiments/frontier-v1/README.md` retains the old world-build pin literal

The "Validation execution-boundary candidate" paragraph still states the runner stops unless the live world-build digest equals `sha256:b5a26d5e2290c7919e4bc629a774f387a766107539b4fcfdf7d55d0f1c19a2c4`. This is accurate today — `pre-validation-artifacts.json` is untouched and still pins that digest, and the payload deliberately does not refreeze — but the sentence becomes false the moment the focused refreeze re-pins `sha256:425bab1c…dae4`. **Consequence:** a stale frozen doc contradicting the refrozen pin if forgotten. **Smallest correction:** update this literal in the focused refreeze commit together with the pin updates (the README is already in the payload inventory, so its digest moves at refreeze regardless).
