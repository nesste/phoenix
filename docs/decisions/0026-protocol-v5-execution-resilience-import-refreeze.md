## Decision

The project chair accepts the seventh independent review and refreezes the §9 execution-resilience payload. Both outcome gates remain closed throughout this import.

Execution resilience is now precommitted. Resume from the last durable pairing-key checkpoint is **mandatory** for an interrupted validation tranche, not discretionary, and abandonment by choice has no representation in the runner: every failed condition returns an error before any launch and the tranche closes indeterminate. `--resume-attestation` must establish no outcome inspection between interruption and resume, digest identity of the frozen bytes with the live schedule and world-build digests compared, a cause on the frozen outcome-uncorrelated list — **OOM struck**, `process_kill` admissible only with an established non-participant principal — classified before the resume decision, and the 72-hour backstop. At most one resume per tranche, corroborated against the `start` entries of the append-only process-event log rather than trusting the checkpoint counter alone.

Two new artifacts exist. **`process-events.jsonl`** is the append-only custodian process-event log required by §9: start, checkpoint, stop and termination entries, each fsynced, carrying timestamps and the originating principal where the host exposes it. Where the host does not — no Go signal handler on either supported host receives the sender's identity — the entry records `exposed: false` with the reason rather than presenting the receiving process's owner as the killer, which is precisely why §9 makes a process kill unsafe absent written establishment. **`scheduled-summary.partial.json`** is the outcome-free progress record, written at every pairing-key boundary, carrying launch index, completed pairing keys, per-arm assignment counts, artifact digests, timestamps and cumulative spend, and nothing else; its field set is asserted in both directions at both levels so a later addition cannot ship an outcome past it.

The **post-closure gate** is encoded in the frozen gate rules. After any validation execution that ends without a completed schedule — interruption, budget stop, or lapse — `requireValidationGate` refuses until four gate fields are set: the closure record's path, an `ACCEPT` verdict, the record's LF-normalized digest, and the independent review of the payload commit that set them. It applies retroactively to the decision-0023 closure, which has no such review; all four fields are pinned empty and `protocol.json` carries the corresponding blocker.

## Two matters this decision must record

**The verdict parser was deleted by chair decision.** Reviews 3, 4 and 5 each found defects in a component that read a review record's prose to corroborate that it stated ACCEPT — each round's defects introduced or left by the previous round's fix. The fifth review recommended deleting it rather than hardening it a fourth time; the chair accepted, and revision 6 replaced roughly 200 lines of frozen code and data with a digest comparison. The sixth review endorsed the deletion and measured its actual cost: run head-to-head against the digest pin, the deleted parser **also accepted an evaluator prompt named as the closure record**, so on the failure most likely to occur it was already worthless. What was given up is machine refusal of a named record whose own prose reads REVISE, or that states no verdict — both inattention cases. What was gained is refusal of a record amended after the review that blessed it, which no reading of current bytes can detect.

**The §5 countersignature clause was struck from blocker 4 by this payload, outside its stated scope.** The §9 payload rewrote `remaining_execution_blockers[4]` to remove the discharged §9 clause and, in the same edit, removed the §5 evaluator-countersignature clause that decision 0025 had already discharged. The third review verified the discharge is genuine and correct; the edit is therefore accurate, but it was not part of the payload's declared change and is recorded here rather than absorbed silently.
