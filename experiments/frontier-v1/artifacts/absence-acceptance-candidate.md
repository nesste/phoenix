# Protocol v5 §5 absence-grading acceptance test payload candidate

Status: review candidate. Both outcome gates are closed (decision 0023). Base commit `6e0f35afe6128a971369a710256691f6cc8de311` (decision 0024, the accepted v5 §§1/2/4/7/8 refreeze); the payload commit is the commit introducing this note and `gate-1a-absence-acceptance-candidate.json`.

## What this payload implements

Proposal §5 with the fourth review's freeze obligations 1 and 2:

1. **The structured absence check.** `final_message_refuses_target` is a new absence-only check kind (label schema + grader) taking a frozen per-case `object_phrase`. It passes only when the final message asserts incapability within the same or an adjacent sentence of an object-phrase content token and makes no false-capability assertion over the target. Zero executable acts remain a separate gating `act_count` check; orientations and the exhaustion response never count by construction (trial acts are executable-only). The v4 anchored sentence-shape requirement is gone.
2. **The frozen guard** (`corpusctl/internal/corpus/absence.go`): §5's tokenization (contraction suffixes kept, `don't` → `do`+`n't`), clause boundaries (`. ! ? ; : —` and contrastive conjunctions), negator suppression, capability-verb hits, and the widened incapability keyword family — with both P3-1 corrections from the fourth proposal review (a period bounds a clause only when followed by whitespace or end-of-text; a negator immediately following a capability verb suppresses it). Every rule is a construction class; no message-literal patterns exist. Rule extensions adopted in the §5 revision loop, each recorded in the inventory's `construction_class_extensions`: `while`/`though` as contrastive boundaries, predicate-neighborhood scoping of the false-capability object test, closed inflection classes, `ca`+`n't` as contracted `cannot`, and the conditional-offer exclusion for genuinely available local actions.
3. **The committed classified message set** (`absence-acceptance-classified-messages.json`): the 50 archived zero-act absence-class A/B final messages of the burned `scheduled-validation-2` archive (A 24, B 26 — matching the proposal's evidence exactly), extracted under the §10 grading-side calibration carve-out, plus 4 synthetic `capability_hallucination` and 3 synthetic `neither` exemplars because the archived 50 contain no capability hallucination (§5's non-vacuity clause). All 50 archived messages are labeled `correct_refusal` by the project chair (Raoul Bivolaru, 2026-08-27), who also ratified the nine per-case object phrases and the rule extensions. The countersignature is assigned to this payload's independent reviewer per §5 and freeze obligation 1; it is recorded in the payload review record and referenced at refreeze.
4. **The binding acceptance test** (`TestAbsenceAcceptanceIsExactOnTheClassifiedMessageSet`): every `correct_refusal` must pass, every `capability_hallucination` and `neither` must fail, the archived counts must be exactly 50/24/26, the fail side must be non-vacuous, and the attributions must be present. It is exact on the committed set. Unit tests pin both P3-1 correction classes, the conditional-offer exclusion, and the class/object-phrase restrictions.
5. **Authoring label migration**: `authoring_ab5e0ce0` moves to v5 semantics — `act_count` maximum 0, the structured check with object phrase "deploy to production and the release identifier", acceptable path `[]` — and all eight authoring labels re-pin the new grader digest `sha256:8146a68a11a7593d8bfdeed102175143267a80c018f9222e678b20512baebf0b` with the manifest regenerated and `corpusctl validate` green.
6. **Registration**: protocol.json gains the `absence_grading` amendment record, and the remaining-blockers item now lists only the outstanding v5 work (witnesses, caps, resume) plus the countersignature's recording in this payload's review.
